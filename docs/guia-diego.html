Parte 1

Qué estudiar

Ordenado de lo más importante a lo menos. Marca cada tema cuando puedas explicarlo en voz alta sin leer; se guarda en este navegador.

  • Intercambio Fi ↔ Fj (swap), escalamiento Fi → k·Fi con k ≠ 0 (scale), eliminación Fi → Fi − k·Fj (eliminate).
  • Ninguna cambia el conjunto de soluciones: cada una se puede deshacer (es invertible).
  • Diferencia con Gauss: Gauss deja la matriz escalonada y luego hace sustitución hacia atrás; Gauss-Jordan hace ceros arriba y abajo del pivote hasta la forma escalonada reducida (RREF), y la solución se lee directo.
GaussJordanService::solveDimensions()
  • Para cada columna de coeficientes, de izquierda a derecha, busca el primer valor distinto de cero desde la fila pivote hacia abajo.
  • Si no hay ninguno: esa columna no tiene pivote, es una variable libre, y pasa a la siguiente.
  • Si el valor está en otra fila: intercambia. Si el pivote no es 1: multiplica la fila por su recíproco. Luego elimina todos los demás valores de la columna.
  • Al final, mueve las filas contradictorias (0 = k) antes de las filas 0 = 0 (moveContradictionsBeforeZeroRows).
  • El número de pivotes encontrados es el rango de A.
  • Única: rango(A) = rango([A|b]) = n (número de incógnitas).
  • Infinitas: rango(A) = rango([A|b]) < n. Variables libres = n − rango.
  • Sin solución: rango(A) < rango([A|b]); aparece una fila 0 = k con k ≠ 0.
  • En el código: si después del último pivote hay una fila con término independiente ≠ 0 → inconsistente; si rango = columnas → única; si no → infinitas.
SystemClassification.php · buildResult()
  • Cada número es numerador/denominador con enteros de precisión arbitraria (brick/math BigInteger): sin redondeo y sin desbordamiento.
  • Siempre simplificado (se divide entre el MCD) y con el signo en el numerador; el denominador siempre es positivo.
  • Es inmutable: cada operación devuelve un número nuevo.
  • Lee enteros, decimales y fracciones: "0.25" → 25/100 → 1/4; "1.5/2" → 3/4; "1/0" se rechaza.
  • Viaja en el JSON como texto ("2/3"), nunca como número de punto flotante.
app/Services/GaussJordan/RationalNumber.php
  • Cada variable libre recibe un parámetro: t, s, r, q, p en ese orden.
  • Cada variable con pivote = término independiente − (coeficientes de las libres × su parámetro). Ejemplo MAT-03: a = 1 − t, b = 1, c = t.
  • Contradicción: se devuelve la fila, left = "0", right = k y la ecuación escrita, por ejemplo 0a + 0b + 0c = 1.
  • El rango nunca supera min(m, n).
  • Subdeterminado (m < n): nunca tiene solución única, porque rango ≤ m < n. Da infinitas o ninguna.
  • Sobredeterminado (m > n): puede dar cualquiera de los tres casos.
  • El contrato acepta rows y columns (2 a 5 cada uno) y conserva size para cuadrados.
  • Flujo: Form Request valida → controlador delgado → servicio calcula → Resource arma el JSON.
  • POST /api/gauss-jordan/solve devuelve siempre los mismos campos: classification, solution, free_variables, parameters, contradiction, verification, initial_matrix, steps, rref (más rows, columns, size, variables).
  • classification es el discriminador: decide qué campos tienen valor.
  • Errores: 422 con {error, message, fields} si la entrada es inválida (el solver no se llama); 500 con mensaje genérico si algo inesperado falla.
  • GET /api/health responde estado, versión y límites, para que el frontend sepa que el backend está vivo.
GaussJordanController · SolveSystemResource · routes/api.php · docs/API-SOLVE.md
  • Cada paso guarda: index, type, notation, description, target_row, source_row, factor, pivot, modified_rows, calculation, before, after.
  • Filas y columnas en base 1 en el JSON. El after de un paso es el before del siguiente (hay una prueba que lo verifica).
  • El frontend solo muestra estos pasos: no recalcula nada. El PDF de Jacob usa el mismo servicio.

Guion para tu parte (unos 6 minutos)

Dilo con tus palabras; no hace falta memorizarlo literal. La línea con borde es lo que dices y debajo está lo que muestras.

  1. 0:00

    Soy Diego, el líder técnico. Mi parte es el núcleo matemático: el algoritmo de Gauss-Jordan, los números exactos, cómo se clasifica el sistema y la API que resuelve, /solve y /health. Todo el cálculo vive en un solo lugar del backend; el frontend y el PDF solo muestran lo que mi servicio devuelve.

    el diagrama de arquitectura del plan (React → Laravel API → GaussJordanService).

  2. 0:45

    El primer problema era la precisión. Si usáramos decimales de computadora, 1/3 se guarda como 0.3333… y los errores se acumulan; además, un 0.0000001 podría parecer un pivote. Por eso creé RationalNumber: cada número es una fracción con enteros sin límite de tamaño, siempre simplificada. Nunca redondeamos, y la respuesta viaja como texto, por ejemplo "2/3".

    el archivo RationalNumber.php, los métodos plus, multipliedBy y normalized.

  3. 1:45

    El algoritmo recorre las columnas de izquierda a derecha. En cada una busca un valor distinto de cero para usarlo como pivote; si está más abajo, intercambia filas. Si el pivote no es 1, multiplica la fila por su recíproco. Después hace cero todo lo demás en esa columna, arriba y abajo. Si una columna no tiene pivote, esa incógnita queda libre.

    la app con el ejemplo 3×3 de Figma, en la pantalla Procedimiento, avanzando paso a paso.

  4. 2:45

    Cada operación se guarda con la matriz antes, la matriz después, la fila que cambió, el pivote y el cálculo término a término. Por eso la pantalla puede explicar cada paso sin hacer cuentas: aquí, por ejemplo, F2 pasa a F2 menos 2F1 para hacer cero debajo del primer pivote.

    el paso 1 con la fila resaltada y el bloque «Cálculo de la fila modificada».

  5. 3:30

    Para clasificar uso los rangos. Si el rango de A es igual al de la matriz aumentada e igual al número de incógnitas, hay solución única. Si son iguales pero menores, hay variables libres e infinitas soluciones. Si la aumentada tiene mayor rango, aparece una fila 0 igual a un número distinto de cero y el sistema no tiene solución.

    el Resultado del 3×3 (única), luego cargar MAT-03 (infinitas) y MAT-04 (sin solución).

  6. 4:30

    La API tiene un contrato fijo: la respuesta siempre trae los mismos campos y classification decide cuáles tienen valor. Antes de resolver, un Form Request valida la entrada; si hay un error, responde 422 indicando la celda exacta y el solver ni se ejecuta. /health sirve para comprobar que el backend está disponible. También soporta sistemas rectangulares, de 2 a 5 ecuaciones y de 2 a 5 incógnitas.

    dejar una celda vacía y pulsar Resolver para mostrar el error marcado; opcional, /api/health en el navegador.

  7. 5:20

    Para asegurar que funciona escribí pruebas automáticas con los casos del plan, de MAT-01 a MAT-06, más 5×5, rectangulares y números grandes: 63 pruebas del backend en verde. Como líder técnico también unifiqué las ramas del equipo en una sola aplicación que se instala con un comando. Con esto termino mi parte; le paso a Jacob, que explicará la validación y el PDF.
